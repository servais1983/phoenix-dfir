# CLAUDE.md: Phoenix DFIR project conventions

Phoenix DFIR is a **local-first, cross-platform** (Windows, macOS, Linux) multi-agent DFIR platform. Forensic tools run **deterministically**. The LLM, local by default, is only used to reason, plan and write.

## Non-negotiable rules

1. **Never invent a forensic result.**
   - Every finding cites at least one reference observed by a tool: `record_id`, `pid`, `line`, `row`, `inode` or `sha256`.
   - Tests and fixtures only contain real data from the repository (`eval/suite/`, `samples/`) or data generated by a versioned script (`eval/build_*.py`).
   - When a tool is missing, say so ("not available"). Never simulate its output.
2. **Evidence is read-only.**
   - Nothing is ever written to `evidence/`, the vault or the originals. Derived files go to `derived/`.
   - SHA-256 is computed at ingestion and verified again at closure.
   - Every action is recorded in the custody ledger (`backend/custody.py`).
3. **Local by default, no leaks.**
   - The default LLM provider is `ollama`, with `llamacpp` as the alternative.
   - A cloud LLM (OpenAI, GitHub Models) requires `PHOENIX_ALLOW_CLOUD_LLM=1` and a consent recorded in the case. **Never** an automatic cloud fallback.
   - Online enrichment (VirusTotal, remote MISP, and so on) is opt-in by key and only sends IoCs, never artifacts.
   - Without an LLM, the deterministic `phoenix triage` mode must work.
4. **No secrets** in code, tests or fixtures. Environment variables are documented in `.env.example`, without values.
5. **Execution safety.**
   - `subprocess` only with an argument list. Never `shell=True`, `os.system`, `eval` or `exec` on data, never `pickle` or unsafe `yaml.load` (use `yaml.safe_load`).
   - Allowlists of plugins and options for external tools.
   - Paths are controlled by `pathpolicy`.
6. **Tool output is untrusted data.** It always goes through `shield.py` before reaching the LLM.

## Cross-platform

- Python 3.10+ and `pathlib.Path`. No hardcoded `/` or `\` separator, no absolute Unix path (`/mnt`, `/tmp`, `/opt`). Temporary files via `tempfile`, data directories via `platformdirs`.
- Compare paths with `Path.resolve()` and `os.path.normcase`. Handle drive letters and UNC paths on Windows.
- Every external tool goes through an adapter in `mcp-server/phoenix_dfir_mcp/adapters/`: `detect()` (per-OS name, `.exe`, `PHOENIX_<TOOL>_CMD`), `version()`, `capabilities()`, `run()`, with a pure Python fallback or a "not available" status.
- `chmod` is best effort, with a warning on Windows. Symlinks are never required: reference the path, do not copy large files.
- Cross-platform web server (waitress, Socket.IO `threading`). `gunicorn` is reserved for Docker on Linux.
- CI matrix on `ubuntu-latest`, `windows-latest` and `macos-latest`. Tests that depend on an external tool use `pytest.mark.skipif` with a reason.

## Architecture (target)

- Installable package `phoenix-dfir` (`pyproject.toml`), `phoenix` CLI: `doctor`, `ingest`, `triage`, `investigate`, `report`, `verify`, `serve-mcp`, `web`, `eval`.
- Agents: orchestrator, triage and collection, logs (EVTX and Sigma), memory, disk and timeline, network, cloud and identity, IoC enrichment, ATT&CK, writer and **verifier**.
  - Each agent has a Pydantic v2 contract (JSON Schema), a tool allowlist and a budget.
  - The blackboard is the case SQLite database (`evidence_db`).
- LLM calls: `temperature=0`, fixed `seed`, output validated by JSON Schema, at most 2 retries (3 attempts), token usage logged.
- The report only includes findings marked `verified` by the deterministic verifier: the reference exists and the cited entities appear in the referenced event.

## Workflow

- **Tests first.** `cd backend && python -m pytest -q` must stay green. Never delete or weaken a test.
- **Small atomic commits** in English, in the imperative mood. One topic per commit.
- Update `CHANGELOG.md` (Keep a Changelog) and the docs when behavior changes. Keep versions and counters consistent.
- Never push, force or rewrite history without an explicit request.
- Lint and security: `ruff`, `bandit -r backend mcp-server`, `pip-audit`, plus `npm run lint` and `npm test` for the frontend.
- Repository text (code, docs, commits) is in English. No em or en dashes. Never reference other projects; integrated tools and connectors may be named.

## Useful commands

```bash
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[all,dev]"
cd backend && python -m pytest -q
phoenix doctor
phoenix triage eval/suite/net_c2_beacon_pcap
phoenix tools
phoenix eval eval/suite -o results                 # needs a local LLM (Ollama or llama.cpp)
```
